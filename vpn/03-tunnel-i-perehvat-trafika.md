## Напоминание: как пакеты ходили раньше

В модуле [[02-kak-rabotaet-internet-bez-vpn]] посылки шли так: приложение → диспетчер ОС (таблица маршрутизации) → реальная дверь (сетевая карта / Wi-Fi, Wireless Fidelity — беспроводная сеть) → провайдер, ISP (Internet Service Provider — поставщик интернет-услуг) → сайт.

VPN (Virtual Private Network — виртуальная частная сеть) **не ломает** эту схему и не «включается в провод». Он делает хитрее: **строит внутри твоего компьютера вторую дверь и переписывает шпаргалку диспетчера**. Перехват происходит ещё до того, как пакет покинул устройство.

## Волшебная дверь: TUN/TAP-интерфейс

ОС (операционная система) умеет создавать **виртуальные сетевые карты** — двери, которых физически не существует. За программной дверью стоит программа, и всё, что в эту дверь падает, попадает прямо ей в руки.

- **TUN** (network TUNnel — «сетевой туннель») — дверь-почтаслот: принимает целые IP-пакеты (IP — Internet Protocol, интернет-протокол). VPN-клиенты используют именно её: туннель работает на уровне IP-адресов.
- **TAP** (network TAP — «сетевой отвод») — дверь пошире: принимает ethernet-кадры целиком. Нужна, когда в туннель надо засунуть целую локальную сеть, LAN (Local Area Network) — например в site-to-site VPN (модуль [[07-arhitektury-vpn]]).

За дверью `tun0` стоит **VPN-клиент** — программа (WireGuard, OpenVPN и др.), которая ловит каждый упавший пакет. Для ОС эта дверь — обычная сетевая карта: у неё есть имя (`tun0`) и свои маршруты. Магия в том, что «кабель» — это просто очередь в памяти между ядром ОС и программой.

## Шпаргалка диспетчера: таблица маршрутизации

Перед отправкой любого пакета ОС смотрит в **таблицу маршрутизации (routing table)** — шпаргалку диспетчера: «адреса такого-вида — в такую-то дверь».

До включения VPN:

```text
куда             куда нести
0.0.0.0/0        → 192.168.1.1 (обычная дверь, домашний роутер)
```

`0.0.0.0/0` означает «вообще все адреса» — это **маршрут по умолчанию (default route)**. После включения VPN клиент добавляет в шпаргалку строку:

```text
куда             куда нести
0.0.0.0/0        → tun0 (волшебная дверь!)      ← главная строка VPN
203.0.113.7/32   → 192.168.1.1 (обычная дверь)  ← исключение, см. ниже
```

Всё. Перехват свершился: диспетчер честно выполняет новую инструкцию и **каждый** пакет несёт в дверь `tun0`, где его уже ждёт VPN-клиент. Никакого взлома — просто ОС сама отдала трафик, потому что её так попросили.

## Почему не возникает бесконечный цикл

Внимательный вопрос: VPN-клиент сам должен отправить зашифрованный пакет **VPN-серверу** через интернет. Если весь трафик уходит в туннель — не завернёт ли пакет в самого себя?

Нет: для IP-адреса VPN-сервера (`203.0.113.7/32`, `/32` — «ровно этот один адрес») в таблице стоит **исключение**: нести в обычную дверь. Более точный маршрут всегда побеждает общий (`/32` точнее, чем `/0`). Туннель снаружи обшивается обычным internet-соединением до сервера — и только внутри него едут твои пакеты.

## Инкапсуляция: матрёшка из пакетов

VPN-клиент получил твой пакет в волшебной двери. Что он делает дальше — **инкапсуляция (encapsulation)**, упаковка матрёшки:

1. Берёт твой пакет целиком (конверт и письмо).
2. **Шифрует** его — содержимое превращается в нечитаемый шум (детали — модуль [[05-shifrovanie-i-kluchi]]).
3. Заворачивает шифротекст в **новый конверт UDP** (User Datagram Protocol — протокол пользовательских датаграмм, «быстрая почта без уведомлений»; WireGuard использует порт 51820, OpenVPN по умолчанию 1194).
4. Пишет на новом конверте адреса: **от тебя — VPN-серверу**.

В интернет уходит пакет-матрёшка. Провайдер видит только внешний конверт: «какие-то данные от 1.2.3.4 к 203.0.113.7, порт UDP/51820». Что внутри — не знает никто, кроме VPN-сервера.

Сервер делает **декапсуляцию (decapsulation)**: снимает внешний конверт, расшифровывает, достаёт твой исходный пакет — и отправляет его дальше в интернет **от своего имени**. Именно поэтому сайт видит IP-адрес сервера, а не твой (подробно — модуль [[04-pochemu-menyaetsya-ip]]).

## Split tunneling: кому в туннель, а кому напрямую

Иногда нужно, чтобы в туннель шло **не всё**. **Split tunneling (раздельное туннелирование)** — это когда в шпаргалке диспетчера появляются избирательные строки:

```text
куда                  куда нести
0.0.0.0/0             → tun0 (почти всё — в туннель)
185.203.1.10/32       → обычная дверь (банк — напрямую!)
192.168.0.0/16        → обычная дверь (домашние устройства — принтер, телевизор)
```

Зачем: банковское приложение ругается на «чужую страну», домашний принтер из туннеля не виден, а тяжёлый трафик торрентов тормозит туннель. Split tunneling даёт выбрать: приватное — в туннель, остальное — как раньше. Обратная сторона: то, что пошло напрямую, провайдер видит как на ладони — приватность становится частичной.

## Итог: полный путь перехвата

1. Приложение создало пакет «сайту 93.184.216.34».
2. Диспетчер ОС сверился со шпаргалкой: `0.0.0.0/0 → tun0`. Отнёс в волшебную дверь.
3. VPN-клиент поймал пакет, зашифровал и упаковал в новый конверт до VPN-сервера (инкапсуляция).
4. Новый пакет пошёл **обычным путём**: реальная дверь → провайдер → интернет. Провайдер видит только внешний конверт.
5. VPN-сервер снял обёртку, расшифровал, отправил исходный пакет сайту от своего имени.
6. Ответ вернулся тем же путём назад и вылез из туннеля у тебя дома.

Перехват не «в сети» — перехват **внутри твоего компьютера**, и делает его твоя же ОС по новой шпаргалке. Дальше разберём, почему из-за этого весь интернет считает тебя сервером: модуль [[04-pochemu-menyaetsya-ip]].

## Словарик сокращений

| Сокращение | Расшифровка | По-простому |
|---|---|---|
| VPN | Virtual Private Network | приватный туннель (модуль 01) |
| TUN | network TUNnel | виртуальная дверь для IP-пакетов |
| TAP | network TAP | виртуальная дверь для целых кадров |
| OS | Operating System | операционная система, «диспетчер» |
| IP | Internet Protocol | язык адресов в интернете |
| ISP | Internet Service Provider | твой провайдер связи |
| LAN | Local Area Network | домашняя/локальная сеть |
| UDP | User Datagram Protocol | быстрая почта без гарантий доставки |
| Wi-Fi | Wireless Fidelity | беспроводная домашняя сеть |
| tun0 | tunnel interface 0 | имя волшебной двери в системе |
